# AGENTS.md

Entry point for any AI agent working on this repository. Read this first, then
`docs/STATE.md`, then `docs/TASKS.md`. Nothing else is required before you start.

This file is written for a capable-but-inexperienced model running unattended.
That means: rules instead of judgement, procedures instead of freedom, and an
explicit statement of what is unknown rather than an invitation to guess.

---

## What this is

**Halcora**: an Arch-based Linux distribution that looks like Xiaomi HyperOS,
ships a Windows-style desktop layout by default, offers a macOS-style layout as
an option, and aims to be unthreatening to people arriving from Windows.

It is **early and untested**. An ISO exists and can be downloaded. Nobody has
ever booted it. The installer has never completed an install. Treat every claim
in the docs, including flattering ones, as a hypothesis.

## The loop you are in

There is no build machine. You edit files, push to `main`, and GitHub Actions
builds the ISO in a privileged Arch container. The human then downloads the ISO,
boots it on real hardware, and reports back. You cannot boot, run, or test
anything yourself.

    you edit  ->  push to main  ->  CI builds  ->  human boots  ->  human reports  ->  you fix

This means **you cannot verify behaviour. You can only verify that CI succeeded.**
Never write that something works. Write what CI said and what the human said.

## Hard rules

1. **Never claim a build, boot, install or fix works.** You have no way to know.
   Report CI status and human reports, and name anything else as untested.
2. **Read a file before editing it.** Every time. Especially one you edited
   earlier in the same session, and especially one another agent edited.
3. **Keep `main` bootable.** Experimental or half-finished work goes on a branch.
   The human needs a buildable `main` at all times.
4. **Respect the 2 GiB limit.** The release ISO is 1.885 GiB with 117 MiB of
   headroom. Adding packages to `iso/profile/packages.x86_64` can break
   publishing. See `docs/STATE.md`.
5. **Small, single-purpose commits.** Follow the existing message style: a short
   imperative summary line, a blank line, then *why*. No signatures, no
   "generated by" lines.
6. **Never add a dependency, framework or package manager** without saying so
   plainly in your reply and being able to justify it from an existing doc.
7. **When CI and your reasoning disagree, CI is right.** Read the log. Do not
   retry the same push hoping for a different result.
8. **Do not touch the legal boundaries.** No Microsoft, Apple or Xiaomi assets,
   fonts or trademarks. `docs/LEGAL.md` explains why. This is not negotiable.
9. **Do not rename the project, the ISO, or the package prefix.**
10. **When you are unsure, stop and ask the human in your reply.** An honest
    question is cheap. A confident invention costs a 40-minute CI cycle and the
    human's trust.

## Where things are

- `docs/STATE.md` — verified current state. **Update it at the end of every session.**
- `docs/TASKS.md` — the ordered queue. Do the first unfinished task only.
- `docs/HANDOFF.md` — procedures, failure-to-action table, glossary.
- `docs/TESTING.md` — the human's test protocol. Give it to the human; don't run it yourself.
- `docs/PROMPTS.md` — copy-paste prompts for the human's next session.
- `docs/DECISIONS.md` — settled decisions (ADR-1 onward). Read before disagreeing with the design.
- `docs/ROADMAP.md`, `docs/REUSE.md`, `docs/DESIGN.md`, `docs/LEGAL.md`, `docs/ARCHITECTURE.md`.
- `iso/` — the live image. `iso/profile/` is the archiso delta, `iso/overlay/` is what gets added to the live root.
- `scripts/` — the two small scripts we actually wrote.
- `packages/` — the theme packages. **They do not exist yet.** Only a README does.

## The three things you must never do to `iso/`

These each broke something once already; the details are in `docs/HANDOFF.md`:

- Change `install_dir` in `profiledef.sh` without changing
  `iso/overlay/etc/calamares/modules/unpackfs.conf` to match.
- Copy Calamares's `etc/` directory into the image. It replaces our config.
- Vendor archiso's `releng` profile into this repo. We are a delta over it.
